# Phone performance scripts (5 Oct 2026)

Node scripts that drive PLAiR on the owner's phone over USB through Chrome DevTools. How and why to use them:
`docs/NEXT_SESSION_PERFORMANCE.md` section 5.

Setup: `adb forward tcp:9222 localabstract:chrome_devtools_remote`. Some scripts hard-code the adb path of an
old scratchpad or `E:/AI_RADIO/client/dist`; adjust before running.

- `state.mjs` - what the phone's tab is doing right now (quality level and levers, scene thread, cover stats, canvases); changes nothing.
- `survey.mjs [panels] [seconds]` - per panel: frames per second and slow frames at rest, then under simulated tilt.
- `ablate.mjs <panel> [rounds] [rest]` - frames per second with coarse covers, flat covers and no scene, interleaved. Frame rate moves in steps of one screen refresh (8.3 ms at 120 Hz), so a saving that does not cross a step shows nothing here: use `budget.mjs` / `frame.mjs` for milliseconds.
- `budget.mjs <panel> [rounds] [extra]` - GPU ms per frame of the scene's main pass and of the covers (full and coarse) by the slope method.
- `frame.mjs <panel> '<json configs>' [rounds]` - settled average frame time for any set of renderer / scene switches plus optional page code (live CSS), interleaved; load a stage with extra copies so the frame is GPU-bound, then compare.
- `gpucaps.mjs` - the phone GPU's float render-target support and whether the coarse cover targets are complete.
- `surfaces.mjs [panel]` - on-screen elements whose CSS makes Chrome draw through an off-screen texture (mask, backdrop-filter, filter, opacity, rounded clips over a canvas).
- `vizframe.mjs [panel]` - one compositor frame: render passes with their rectangles, and the layers.
- `cssab.mjs <panel> '<json {label: css rules}>' [rounds] [extra]` - GPU cost of page styling: the frame is loaded so it is GPU-bound, each set of CSS rules is injected in turn and the frame time compared with "as is".
- `toggle.mjs [button title] [rounds] [panel]` - opens and closes a player panel (default "Manage devices") and prints frames drawn, average and worst frame and long frames.
- `touchfps.mjs [panel] [seconds] [x,y]` - frames per second without and with a synthetic finger moving on the screen (Chrome holds page frames to 60 Hz unless the screen is touched).
- `copycost.mjs [size] [rounds] [targets]` - cost of WebGL-to-2D-canvas copies, the way covers reach the screen (10 small covers: about 0.7 ms a frame).
- `scenecopy.mjs [rounds]` - cost of copying out of the live background canvas (about 1.7 ms a frame for the first copy; why edge-fade strips fed from the scene were rejected).
- `fillcheck.mjs <out dir> [dark]` + `fillcheck_diff.py <dir>` - pixel check on the phone of the mask-free fills against the masked originals; the diff script compares any `*_old.png` / `*_new.png` pair.
- `tab.mjs open <url> | front <part> | close <part> | list` - tabs in the phone's Chrome. The owner runs PLAiR as an installed app, so a second tab is confusing for them: prefer deploying.
- `oldnew.mjs [panels] [rounds] [seconds]` - the deployed build against the 14 Nov morning behaviour (atlas forced to 3840x1024, radio-button code back in the panel-interior shader), interleaved, frames per second at rest and under tilt. Frame rates taken an hour apart are not comparable; this is.
- `scenepass.mjs [panel] [rounds] [extra] [variants]` - ms per main scene pass by the slope method, with the two glass shaders edited live (`VARIANTS_FILE=./scenevariants.mjs` adds the interior-shader variants).
- `atlassize.mjs [rounds] [extra] [sizes]` - Now Playing frame time with the cover atlas forced to each size (Chrome copies the whole atlas every frame: 0.7 ms per megapixel).
- `atlasresize.mjs [panel] [rounds]` - frames around a forced atlas resize, and how long the resize blocks the page (4-6 ms per dimension).
- `trailshare.mjs` - share of each on-screen cover's pixels that take the edge-fill path (`PANEL=Catalog`).
- `sharevideo_phone.mjs [close|stay]` - a full share video on the phone through the app's own buttons (closing the Share window mid-render by default): time, frames per second of the app meanwhile, the page's stage timings. It publishes under the signed-in account: only when the owner asked.
- `sharebench.mjs '<json {label: options}>'` - short share-video renders with the pipeline's bench switches (`seconds`, `canvasFrames`, `noEncode`, `flatShader`, `encoder`, `keyFrameEvery`, `sampleFrame`, `batchFrames`, `keepVisuals`, `closeWindow`, `css`); prints speed, bitrate, ms per frame and, with `sampleFrame`, the decoded frame and its two neighbours against the rendered one (PSNR, colour shift). Nothing is uploaded.
- `workerprof.mjs [seconds] [name part]` - CPU profile of a worker of the phone's page while it runs (default: the share-video worker): self time by function, native calls charged to their callers. Start the work first (a long `sharebench.mjs` clip).
- `readbacktest.mjs` - how long each way of reading pixels back from WebGL2 blocks on the phone (pixel-pack buffers with a fence by usage hint, reuse and extra waiting; `readPixels` straight into memory). Nothing is shown.
- `encbench.mjs [frames]`, `encbench_i420.mjs [frames] [names]` - the device's video encoders alone: frames a second and bitrate per configuration, from a canvas and from ready-made frames in memory.
- `roloop.mjs install|read|remove` - what was written in the frames where Chrome raised a ResizeObserver loop error.
- `insetsync.mjs [button title]` - opens and closes a player panel and checks frame by frame that the panels keep their distance to the player.
- Any of these also drive the desktop: `node ../headless.mjs <url>` keeps headless Chrome open on the P6000, then run the script with `CDP_PORT=9338 PAGE=<part of the url>`.
- `lookpass.mjs [panel] [rounds] [extra] [looks]` - ms per main scene pass for each background look (cover, split, depth) with the colour split forced on and off; every shot of the song's plan is given the look, the plan is put back at the end; panel `none` leaves the screen as it is (fullscreen visuals). All the look scripts take the slope between two loaded points (N and 2N extra passes): a frame that is not GPU-bound reads as free.
- `lookfull.mjs [rounds] [extra] [programs]` - each scene program (`interior`, `cover.backdrop`, `split.full`, ...) drawn alone over the whole screen, which is what fullscreen visuals cost.
- `lookstages.mjs <program> '<json {label: [[from, to], ...]}>' [rounds] [extra] ['<json pinned uniforms>']` - one program over the whole screen with its fragment source edited live, interleaved: the way to find what a shader stage costs before changing code.
- `lookparts.mjs [panel] [rounds] [extra] [looks]` - one pass with a panel open, then with the interior, full and backdrop shaders each drawn flat.
- `skipseries.mjs [skips] [panel] [warm-up]` - a series of presses of Next (single skips vary by 150 ms): frame time lost in the 1.5 s after each press, worst frame, and the long frames split into script by source, end-of-frame style and layout, and the rest. `FRAMES=1` prints each long frame. The number to compare before and after a change.
- `skipprof.mjs [min ms] [depth] [seconds]` - CPU profile of one press of Next as a call tree by inclusive time, with a snippet of the built file at each function; `SELF=40` lists self time with native calls charged to their callers, `ENTRIES=1` lists the app's own functions by inclusive time. Needs `client/dist` to be the build the phone runs.
- `skipstyle.mjs [min ms] [seconds]` - trace of one press of Next: every style recalculation and layout with the elements touched and what invalidated styles before it.
- `catalogpick.mjs [picks] [warm-up]` - taps Catalog cards one after another: ms from the tap to the card's first answer, to the playing mark and to the player, frame time lost in the 1.5 s after, long frames split into script, style and the rest. `SCROLL=1800` scrolls first and prints the frame rate; `VARIANTS='{"label": "css" or {css, art, scene}}'` runs a series per variant in turn.
- `coverwatch.mjs [distance] [speed] [rounds]` - scrolls the Catalog down and back and, every frame, counts the covers on screen that are not shown yet, still fading in, or fully there (what "the covers were gone when I scrolled back" measures), and the cards that are not there at all (fewer on screen than at rest: the list lost its place). `DIRECT=1` moves the list by its scroll position, for desktop Chrome; `IDLEMB=<n>` sets the renderer's idle cover budget for the run; the last line is the renderer's texture count and memory. `catalogpick.mjs 0 0` with `SCROLL=<px>` gives the scroll frame rate without picking songs.
- `catstate.mjs [shot.jpg]` - what the phone's Catalog shows right now, read-only: a screenshot, the open tab, each list's scroll position and first text, cover canvases by size and the last catalog requests.
- `sortswitch.mjs [modes] [wait ms]` - taps the Catalog's sort buttons in turn (default Remastered, A-Z, Recent, Genre, Recent) and reports after each tap the scroll position, cards on screen with a title against skeletons, the catalog requests made and console errors. Scroll the list down first: the 17 Nov bug (skeletons until the next scroll) only shows away from the top.
- `windowstate.mjs [tap] [wait ms]` - the Catalog's paged track window (`useVirtualWindow`) read from React's fibers: pages held and pending, the queue, total, sequence number and the last range the list asked for; optionally taps a sort button first.
- `scrollerstate.mjs [tap] [ms]` - taps a sort button and records every frame the Catalog list's `VirtualScroller` internals (instance, items, window start, demand key, items version, rendered range, measured list top) next to the paged window's state; one line per change. A demand key whose version lags the items version means `compute()` returned before asking for pages (17 Nov: the `Scroller`'s ref was null during the list's layout effect).
- `handoff.mjs [rounds] [seconds] [covers] [modes]` - how cover-sized WebGL pictures reach the screen, every card changing every frame, app covers and background paused: `copy` (one WebGL canvas, copied into each card's 2D canvas: today's path), `handoff` (OffscreenCanvas + `bitmaprenderer`, no paint job), `one` (the single WebGL canvas shown itself), `draw` (no display). 17 Nov, 8 covers: copy 46.8 fps, handoff 45.6, one 59.9, draw 59.9 (60 = the untouched screen's rate): the cost is one changing canvas per card, not the copy.
- `scrollab.mjs [panel] [rounds] [distance] [speed] ['<json variants>']` - what each part costs while a panel is scrolled with a synthetic finger (frames per second, slow frames, frame time lost), switches applied in turn: arrival fades off, covers flat, no scene, or any `{art, scene, css, js, undo}`.
- `scrollprof.mjs [panel] [distance] [speed] [rounds]` - CPU profile during that scroll: script, garbage collection and the rest per second, self time by function with native calls charged to their callers, and the scripts inside the long frames with the time each spent forcing style or layout. `PICK=3` profiles three Catalog picks instead.
- `scrolltrace.mjs [panel] [distance] [speed] [rounds]` - trace of that scroll (or of one pick with `PICK=1`; `ART='{"skipDraw":true}' SCENE='{"skip":true}'` traces the floor with no covers drawn and no background; `THREADS=CrGpuMain,CompositorGpuThread,...` adds those threads' self time by event and the page's and the display's frames a second): busy time per thread (page, compositor, GPU process), the page's self time by kind of work, and every layout or style recalculation that script forced, by the function that forced it.
- `skipcpu.mjs <skips> <label>=<port>,<page match> ...` - main-thread CPU time in the 1.5 s after a press of Next from a CPU profile (busy, script, garbage collection, the rest), for one or more pages pressed in turn: old and new builds side by side in headless Chrome (`headless.mjs`), or the phone alone. `skipseries.mjs` takes `CPU=6` to slow a desktop page, but its frame times swing too much there to compare builds.
- `renders3.mjs [panel] [seconds]` - every React commit after one press of Next with the roots of its cascades; `TYPES=1` lists the components in the biggest commit and which props changed on each, `TYPES=all` sums them over every commit. Reloads the app twice.
- `waveshot.mjs <out.png>` + `wavediff.py <before.png> <after.png>` - the player's waveform in device pixels with the song and how far it has played, and the comparison of two captures of the same song.
- `skipwatch.mjs [seconds]` - one press of Next: slow frames after it, the background scene's own steps and frames, and every long animation frame with the scripts in it (a script's position is its character offset in the built `index-*.js`).
- `cdp.mjs` - shared helper: attach to the plair.live tab (`PAGE=<part of another address>`), `send`, `evaluate`, `sleep`, and `openPanel`, which never taps the tab that is already open (that toggles Radio between Talk and Text and the Catalog between tracks and shoutouts; a script did exactly that to the owner's setting on 14 Nov).
- `interleave.mjs <panel> '<variants json>' <rounds> [reload]` - interleaved A/B under simulated hand-held tilt; medians.
- `tiltsurvey.mjs <panels> <seconds>` - fps per panel under simulated tilt, with the renderer's draw-mode counts.
- `slope.mjs <panel> '<variants json>' [reload]` - slope method (extra passes) for GPU cost per stage.
- `ctxloss.mjs '<variants json>' <rounds> [panel]` - reload, then interleaved switches under simulated tilt, logging every WebGL context created or lost; stops at the first real loss. Run `adb logcat` alongside: Chrome logs the GPU reset reason there.
- `stages.mjs '<stage,stage>' <rounds> [extra passes]` - GPU ms per cover pass on Now Playing (`PANEL=` for another) by the slope method; `LOW=<n>` takes the slope between n and n + extra passes instead of from 0 (the GPU clock differs at rest), `SKIP_SCENE=1` pauses the background scene for the run (forced full pass + N extra passes, fixed tilt, fixed light level, settles after each shader swap), for shader variants from `edits.mjs` (live source edits, no build); interleaved rounds, medians.
- `identity.mjs '<stage,stage>' <out dir> [panel]` - reads the largest on-screen cover's own canvas with tilt and lights frozen and compares every pixel to the first shot (mean, max, % of pixels off by >2 / >8), saving PNGs and x8 diff images. Put `reference` first to score variants against a 96-step march.
- `edits.mjs` - the shader variants both use (`as is`, `lights off`, `no parallax`, `reference`, ...; `L4 const`, `L4|L2|L1 ubound`, `L off` and their ` coarse` twins time the cover lighting with 4 fixed test lights and the light loop bounded by a uniform). Stages run at full resolution; `coarse` is its own stage. The cover pass varies 2-3 ms with the cover, so compare stages inside one round (`stages.mjs` prints the song). A stage can carry `derive`: page code that turns the uniforms the renderer set into new uniforms before each draw, to time per-cover values without a build (cover uniforms the edited shader drops get stand-in locations so their values are still seen). Run `identity.mjs` on a derive stage before timing it: a broken one draws less and reads fast.
- `derivecheck.mjs [stage]` - applies a derive stage and prints the uniforms the renderer set and the values derived from them.
- `shadercompile.mjs` - compiles and links the working copy's cover programs on the phone's GPU in a throwaway WebGL2 context (`FALLBACK=1` for the WebGL1 programs) and lists each program's active uniforms. Nothing on screen changes.
- `flingstages.mjs '<stage,stage>' [rounds] [distance] [speed]` - Catalog fling page rate (rAF updates a second) with cover-shader stages applied in turn, coarse off: a build's shader change measured in a fling without deploying.
- `buildcheck.mjs <out dir> <page part> ...` - for pages open in `headless.mjs`: GPU, cover textures, console warnings, and the first Catalog tile lights off (tilt pinned) and on, saved as PNG. The big tile shows each guest's own current track, so two fresh guests do not show the same cover.
- `soak.mjs <rounds>` - fresh reload, then motion on Now Playing, watching for WebGL context loss.
- `catwhy2.mjs <px/s>` - catalog fling, classifies every blank tile per frame (no data / no pack / decoding / ready not drawn).
- `fadeab.mjs` - skips with the theme transitions on vs off.
- `renders2.mjs <panel>` + `renderhook.js` - React re-render counts after a skip, charged to the root of each cascade.
- `cpuprof.mjs`, `cpucallers.mjs` - CPU profile of a skip, top functions and who calls the layout-forcing getters.
- `loaf.mjs` - long-animation-frame entries after a skip.
- `skiptrace.mjs` - Chrome trace of a skip, summarised in memory (write large traces to E:, never to C:).
