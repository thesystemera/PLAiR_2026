# Vector Database Architecture - The TTS Pattern

**Date:** 2026-01-02 (updated 2026-09-26 for PostgreSQL, 2026-10-01 for the mpnet encoder and semantic sources)
**Status:** Production Architecture

**What changed in September 2026:** every searchable source (tracks, shoutouts, local knowledge, news, places, listener requests) shares `BaseVectorDatabaseService` and one encoder, `SEMANTIC_ENCODER` (all-mpnet-base-v2, 768-dim). Embedding tables and index files carry the encoder slug (`<category>_mpnet_embeddings`, `<prefix>_mpnet_1.ann`), so a new encoder rebuilds cleanly. Search ranks every item with per-query category weights (`services/semantic_source.py` `SemanticSearch`); the Annoy indexes are still built with the rowid mapping below and are used for seed radio. `CLAUDE.md` section 15 ("Semantic sources") is the maintained summary.

This document describes the rowid-based vector database pattern used across the system. This pattern has been proven stable in TTS services for months and is now used by both catalog and user_content vector databases.

> **History:** The pattern originally relied on SQLite's implicit `rowid`. SQLite was migrated to PostgreSQL on 2026-02-01 (backups in `data/sqlite_backup_2026_02_01/`). PostgreSQL has no implicit rowid, so the `tracks` and `shoutouts` tables now declare an explicit `rowid` identity column that plays the same role.

---

## Core Concept

**The Pair Pattern:** PostgreSQL table + Annoy index (.ann) work together via an integer `rowid` column.

**Key Insight:** `rowid INTEGER GENERATED BY DEFAULT AS IDENTITY UNIQUE` is a persistent auto-incrementing integer (starting at 1) that serves as the mapping between Annoy indexes and database records. No separate mapping file needed. (An in-memory `rowid → id/metadata` cache is populated during rebuild purely as a lookup speed-up; the DB remains the source of truth.)

**The Mapping Formula:**
- `annoy_index = rowid - 1` (when building)
- `rowid = annoy_index + 1` (when searching)

## Database Schema Pattern

### Catalog (`tracks` table, `ai_radio_catalog`)
```sql
CREATE TABLE IF NOT EXISTS tracks (
    rowid INTEGER GENERATED BY DEFAULT AS IDENTITY UNIQUE,
    track_id TEXT UNIQUE NOT NULL,  -- The UUID string identifier
    metadata_json TEXT NOT NULL,
    created_at TEXT,
    title TEXT,
    ...
)
CREATE UNIQUE INDEX IF NOT EXISTS idx_track_id ON tracks(track_id)
```

### User Content (`shoutouts` table, `ai_radio_user_content`)
```sql
CREATE TABLE IF NOT EXISTS shoutouts (
    rowid INTEGER GENERATED BY DEFAULT AS IDENTITY UNIQUE,
    content_id TEXT UNIQUE NOT NULL,  -- The UUID string identifier
    metadata_json TEXT NOT NULL,
    created_at TEXT,
    ...
)
CREATE UNIQUE INDEX IF NOT EXISTS idx_content_id ON shoutouts(content_id)
```

### TTS (`settings.TTS_EMBEDDING_TABLES`, `ai_radio_embeddings`)
```sql
CREATE TABLE IF NOT EXISTS tts_embeddings (
    id SERIAL PRIMARY KEY,
    filename TEXT UNIQUE NOT NULL,
    title TEXT,
    embedding BYTEA,
    voice TEXT
)
```
TTS tables use `id SERIAL` in the same role (`add_item(id - 1, ...)`, `WHERE id = annoy_idx + 1`).

### Category Embedding Caches (`ai_radio_embeddings`)
```sql
CREATE TABLE IF NOT EXISTS mood_mpnet_embeddings (text TEXT PRIMARY KEY, embedding BYTEA NOT NULL)
```
One table per category, named by `base_vector_database_service.embeddings_table(category)` (`<category>_<encoder slug>_embeddings`); created on startup if missing.

**Pattern:** Use TEXT UNIQUE NOT NULL for the string identifier and a separate integer identity column (`rowid` / `id`) for the Annoy mapping.

        combined_embedding = self._create_weighted_embedding(category_embeddings)

**Key Points:**
- Query with `ORDER BY rowid` for deterministic ordering
- Extract category texts on-the-fly from metadata_json
- Use `rowid - 1` as the Annoy index
- Populates `_track_rowid_cache` / `_track_metadata_cache` as a lookup speed-up

## Search Flow

Text search no longer walks the Annoy index. `catalog_vector_search_service.search()` and the shoutout search hand the query to `SemanticSearch` (`services/semantic_source.py`), which works out category weights for the query (regex presets or the query-intent prompt cache), scores every item's per-category embeddings and ranks them all. The same class serves news, places, local knowledge and listener requests.

The Annoy indexes serve "more like this track" (seed radio): Annoy returns item ids, and `rowid = annoy_index + 1` maps each back to its row, first through the in-memory `_track_rowid_cache` / `_content_rowid_cache`, then `SELECT ... WHERE rowid = %s` as the fallback.

## Why This Pattern Works

### 1. Survives Restarts
- **Problem:** In-memory dicts lost on restart
- **Solution:** rowid persisted in PostgreSQL

### 2. No Separate Mapping Files
- **Problem:** Separate mapping files drift from the database
- **Solution:** Query database directly for all metadata

### 3. Deterministic Mapping
- **Problem:** Enumerate-based indexing changes order
- **Solution:** `ORDER BY rowid` ensures consistent ordering

### 4. Proven Stable
- **TTS Services:** Used this pattern for months without issues
- **Now:** Catalog and user_content use same proven pattern

### 5. Simpler Architecture
- **Kept:** PostgreSQL (metadata) + Annoy .ann (vectors)

## Startup Flow

1. `catalog_database_service.initialize()` - Syncs catalog JSON metadata (`CATALOG_DIR/metadata/*.json`) into `ai_radio_catalog.tracks` (upsert; new rows get new rowids, removed files are deleted)
2. `user_content_database_service.initialize()` - Syncs shoutout JSON files into `ai_radio_user_content.shoutouts`
3. `catalog_vector_db_service.load_initial_data()` - Creates category embedding tables if missing, loads cached embeddings into memory, loads `.ann` files
4. `user_content_vector_db_service.load_initial_data()` - Same for user content
5. **Index validation:** each `.ann` file's `get_n_items()` is compared to `MAX(rowid)` in the DB. Missing, empty, or stale indexes trigger a full rebuild.

**THE KEY TEST:** Restart server - vector search still works (rowid mapping persisted in Postgres).

## File Structure

### Annoy Indexes (`data/embeddings/`)
```
data/embeddings/catalog_mpnet_1.ann, catalog_mpnet_2.ann             # Catalog (A/B double buffer)
data/embeddings/user_content_mpnet_1.ann, user_content_mpnet_2.ann   # User content
data/embeddings/news_mpnet_*.ann, places_mpnet_*.ann, local_knowledge_mpnet_*.ann, listener_requests_mpnet_*.ann
data/embeddings/tts_embeddings_1.ann, ...                            # TTS (tts/paralanguage/impulse/breath/audio)
```

### Source Files (Persist)
Catalog media lives outside the repo, at `CATALOG_DIR` from `.env` (currently `D:/catalog`; `settings.CATALOG_DIR` defaults to `server/catalog`):
```
CATALOG_DIR/metadata/*.json         # Original track metadata
CATALOG_DIR/mp3/, opus_128k/, ...   # Audio files
CATALOG_DIR/users/<user_id>/        # User shoutout JSON + audio
```

**Pattern:** Delete `.ann` files to force a rebuild from the database. The DB itself is re-synced from JSON on every startup.

## Summary

**Database Pair:** PostgreSQL table (metadata) + .ann (vectors) = Complete system

**Mapping:** Annoy index ↔ `rowid` identity column (deterministic, persistent)

**Build:** Query database `ORDER BY rowid`, use `add_item(rowid - 1, embedding)`

**Search:** Annoy returns indexes, query database `WHERE rowid = annoy_idx + 1`

**Stability:** Survives restarts. Stale indexes are detected on startup and rebuilt. Proven pattern from TTS.
