## How to run

- **Start / restart:** the desktop shortcut **PLAiR Start** runs `external_components\plair_start.bat`, which:
  1. stops PLAiR only;
  2. runs `npm run build`;
  3. reloads nginx;
  4. starts the backend window "Plair Backend (Port 8000)";
  5. waits for health on 8000 and 8090;
  6. runs `tests/smoke_test.py`.
- **The shortcut runs as administrator.** An agent in a normal shell cannot stop an admin-started backend, so restarts must go through the shortcut.
- **Never use `restart_all.bat`.** It kills every python, node, nginx and java process on this shared machine.
- **Smoke test:** `E:/AI_RADIO/.venv/Scripts/python.exe tests/smoke_test.py [--skip-dj]` (10 checks).
- **Machine etiquette:**
  - The RTX 6000 (nvidia-smi index 1) belongs to the owner's DeepPBR work. Never use it: headless Chrome needs `--disable-gpu`, CPU tests need `CUDA_VISIBLE_DEVICES=-1`.
  - Only run PLAiR for testing.

## Responsiveness regression (open, top priority)

**Symptom:** track changes and general response feel much slower after the latest changes. Try a fresh boot first; several changes had not been live together before. If it's still slow, profile before changing anything.

Candidates, most likely first:
1. **Client transport path on next/prev:**
   - optimistic next/prev in `PlaybackContext.jsx` (regression agent);
   - `audioEngine.js` hold logic (`armHold`/`resumeFromHold`) for Radio Mode;
   - the latest-wins transport.
   - Check timing from tap to audio with DevTools Performance and `[AudioEngine]`/`[PlaybackContext]` logs.
2. **Document-level micro-interaction listener** in `microMotion.js`: `ui-tap`/`ui-press` on every pointer event, plus `arrivalGlow`/`arrivalPulse` and the new queue auto-scroll (`Queue.jsx`).
3. **Backend `next`:** `playback_state.py` refills the queue before advancing, with a bounded 0.3 s prefill before broadcast, under a per-session ordered lock. Check `[PLAYBACK]` timings and whether the lock waits on DB or analytics work.
4. **GPU contention on the P6000:** the voice engine now also runs background exact-refresh renders (up to 40/h), clock and ID pre-renders, and breath refreshes. That shouldn't affect music track changes, but it can slow the DJ and Radio Mode preparation.
5. **Catalog/artwork prefetch** (`artworkPrefetcher.js`, 6 concurrent requests) competing with audio fetches.
6. **Service worker** changes (`client/public/sw.js`) from the offline polish.

Useful knobs: `QualityContext` (`localStorage plair_quality_tier` = 0–4, `window.__plairQuality()`), `TTS_EXACT_REFRESH_ENABLED=false`, `STINGS_ENABLED=false`, `RADIO_*` settings.
